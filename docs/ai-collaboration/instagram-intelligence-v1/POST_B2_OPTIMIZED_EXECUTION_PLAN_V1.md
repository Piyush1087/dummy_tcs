# Instagram Intelligence — Post-B2 Optimized Execution Plan V1

## Adopted authority

This artifact records the Parent-adopted post-B2 packet order. It is execution
routing, not a Product, UX, provider-scope, Evidence-lifecycle, or
Intelligence-ownership redesign.

```text
B2 = ACCEPTED
PRIMARY_SEQUENCE = B3A -> B4 -> B3B -> C2 -> C3 -> C4
B4 = PROHIBITED_PENDING_B3A_ACCEPTANCE
```

The split keeps the first secure media proof independently reviewable before
consumer/UI proof or broader media handling:

- **B3A**: one selected IMAGE only—contained ephemeral locator acquisition,
  hardened bounded download, temporary artifact, technical metadata, one
  low-level model-neutral visual observation, exact DE lineage, and cleanup.
- **B4**: direct authenticated proof route only. It does not own peer
  navigation convergence.
- **B3B**: the remaining V1 media acquisition lanes—deterministic carousel
  representative-child inspection and Reel/video cover-or-thumbnail
  inspection—under separate authority.
- **C2**: deterministic foundations required by later semantic work.
- **C3**: the complete per-media semantic observation and likely-collaboration
  lane; B3A does not pre-implement it.
- **C4**: the three accepted Instagram Intelligence Objects.

## Post-C4 separately authorized branches

After C4 acceptance, the following proceed only under their own packet
authority and may be scheduled independently where predecessor contracts permit:

1. C1 sync coordination and operational sequencing.
2. Wave E workspace/navigation/UI work.
3. The conditional hidden Brand lane, only if its explicit evidence cutline and
   separate authority are satisfied.

No branch may infer acceptance from code presence, share mutable current or
candidate state, or bypass the accepted source-isolation and generation-only
rules. E1 remains sole owner of peer-navigation convergence.

## Canonical V1 coverage

- All eligible posts: metadata, caption, metrics, and coverage.
- Deep-selected corpus: at most 24 posts.
- Selected IMAGE: visual inspection.
- Selected CAROUSEL: deterministic representative-child inspection.
- Selected REEL/VIDEO: cover or thumbnail inspection only.
- Unselected media: `NOT_INSPECTED` with visual semantic `UNKNOWN`.

B3A does not choose the 24-post corpus and does not implement carousel,
video-cover, analytics, likely-collaboration, Object, current-state, consumer,
UI, refresh, or scheduling behavior.

## V1.1 media deferrals

Deferred beyond V1 are full video/frame sampling, audio acquisition,
transcription, temporal multimodal analysis, inspection of every carousel child,
durable raw-media mirroring, and any broader provider-media acquisition. These
deferrals cannot be pulled into B3A/B3B without new authority.

## Optimized verification model

Each packet uses the narrowest evidence set that proves its boundary:

- deterministic provider, DNS, transport, decoder, and model fixtures for
  security and truth-state boundaries;
- contract/unit suites for exhaustive failure matrices;
- one clean PostgreSQL 17 route where persistence, fencing, lineage, deletion,
  replay, or tenant isolation is changed;
- focused B1/B2 regressions where their contracts are reused;
- Owned Website regression only when a shared runtime surface changes;
- browser/accessibility proof in B4/Wave E, not in backend-only B3A;
- no unrelated full-suite execution and no optional live read as an acceptance
  substitute.

Every implementation packet remains separately committed, normally pushed,
independently fetched back, and reviewed before its successor is authorized.
