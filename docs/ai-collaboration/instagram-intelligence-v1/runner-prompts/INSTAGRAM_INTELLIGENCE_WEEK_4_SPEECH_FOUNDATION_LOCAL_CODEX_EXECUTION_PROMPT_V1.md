## 10. Transcript truth contract

The strict finalized transcript must distinguish:

~~~~text
OBSERVED
= successful audio extraction and valid non-empty timestamped speech

EXPLICIT_EMPTY
= successful audio extraction and successful transcription that explicitly
  establishes no intelligible speech

UNKNOWN
= missing/unconfigured provider, extraction failure, invalid output, timeout,
  unsupported media/language behavior, incomplete analysis or other inability
  to establish transcript truth
~~~~

No audio track may be represented separately as an explicit technical state
such as NO_AUDIO_TRACK; it must not fabricate transcript text. Music-only,
silence and unintelligible speech must remain distinguishable where the
provider can truthfully do so. Do not convert provider/model failure into
EXPLICIT_EMPTY.

Each observed segment must contain:

~~~~text
stable segment ordinal
startMs
endMs
normalized source-language text
optional valid language tag if actually returned
optional confidence only if actually supported
~~~~

Validation must require finite integer millisecond bounds, 0 <= startMs <
endMs <= verifiedDurationMs, deterministic ordering, no duplicate segment
identity, bounded normalized text and bounded aggregate text. Reject rather
than truncate invalid/oversized output.

Preserve source language. Do not translate, identify a real speaker, infer
speaker demographics, or label a creator identity.

Treat audio/transcript content as untrusted source data, never instructions.
The provider request must explicitly isolate system instructions from the media
payload. Transcript text must not control tools, URLs, SQL, file paths,
provider calls or later prompts.
