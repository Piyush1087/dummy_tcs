## Implementation learning — evidence, not user-research claims

Manual-first kept canonical mutation independent of source/model/runtime availability and enabled the same real editing path for no-source and connected users. Meaningful cost lay in canonical transaction/audit integrity and clear optional suggestion projection, not a second Intelligence runtime. The P3 guard correction demonstrated that reusing source-dependent workspace access mechanically would have violated manual-first Product.

Inline suggestions reuse the same editable fields, target-only confirmation and existing current contracts rather than a competing Suggestions workspace. Actual tests prove integration and source-independent recovery; they do not prove user preference, conversion or comprehension. Effectiveness versus a separate Intelligence presentation remains a Product research question, not a claimed measured outcome.

The reusable pattern is one business-owned canonical aggregate + immutable authored revisions + optional independently owned Evidence-backed suggestions + strict discriminated commands + existing Team actor/Owner subject. Reuse requires compatible ownership; no generic multi-domain profile system was introduced.

Actor identity must remain distinct from canonical Owner subject. Delegated Manager/Assistant sessions read the same Owner context, with immutable actual-actor provenance. Brand access outside the source guard preserves that invariant without rewriting the inherited Entry lifecycle.

Five authorized families and bounds were technically sufficient to implement all frozenV0 behavior without schema/runtime/API expansion. Missing support truthfully suppresses suggestions; Bio remains manual-only and loose palette cues cannot become exactHEX. This establishes technical sufficiency, not that five families satisfy every future Creator need.
