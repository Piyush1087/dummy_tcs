## 1. Audience Product decisions validated

Implementation validates the frozen Audience V0 direction:

- one read-only factual Audience section inside the durable Insights workspace;
- source/freshness context near the top;
- Audience-level deterministic Highlights independent of the selected cohort;
- one whole-section Followers / Engaged cohort switch;
- unusable cohorts hidden from selection while truthful availability remains visible;
- account follower count remains independent from demographic-cohort usability;
- count-only demographic distributions are acceptable when denominator authority is unavailable;
- no fabricated percentage, zero, concentration, or causal inference;
- no LLM is required for Audience V0;
- Owner, Manager and Assistant may share one explicit read action without receiving mutation authority;
- weekly processing, no manual Audience refresh, dynamic freshness and failure-current preservation are appropriate;
- Creator Settings remains source lifecycle authority.

No Audience V0 Product decision needs to be reopened before the next Creator Centre Product phase.

## 2. Platform architecture lessons to carry forward

Audience established durable shared infrastructure that future Creator Intelligence must reuse:

```text
Brand / Creator typed owner scope
→ shared DE
→ Evidence
→ verified Intelligence execution
→ generation / transition / CAS / current
→ shared scheduling
```

Future Creator Intelligence sections must not introduce:

- a parallel Creator DE runtime;
- a Creator-only Intelligence current store;
- a second scheduler;
- synthetic Brand ownership;
- direct feature writes around the canonical shared Intelligence runtime.

Provider adapters should continue to own credentials and provider-specific acquisition. Shared/runtime layers should receive bounded source truth. Deterministic application finalizers should own display-safe factual derivation where possible.

## 3. Product-contract lessons for future Insights sections

Before implementation of each future Insights section, Product must freeze:

1. the creator question the section answers;
2. exact source-native facts it may expose;
3. source cadence and freshness semantics;
4. empty / partial / unavailable behavior;
5. truth that may be deterministic versus semantic/model-derived;
6. what happens when a prior valid current exists and refresh fails;
7. whether the section owns any user action or is read-only;
8. cross-platform semantics and whether any comparison is genuinely compatible;
9. Media Kit projection boundaries separately from workspace truth.

Provider capability absence must remain distinct from provider/integration failure.

Source-native semantics must not be forced into an Instagram-shaped canonical model when YouTube, TikTok or later platforms are added.

## 4. Frontend/Product lessons

The first Insights slice validates a pattern for future Creator Centre read-oriented intelligence:

```text
purpose / source context
→ compact Intelligence summary
→ source-native exploration
→ truthful coverage / freshness / recovery state
```

Future sections may reuse the shell, strict consumer/client/state pattern and responsive primitives, but their visible hierarchy remains a Product decision.

Do not add empty future tabs or placeholder navigation merely because the durable workspace architecture anticipates later sections.

## 6. Other implementation lessons

The following are engineering/process lessons rather than Creator Product scope:

- integrated acceptance must begin at the production-shaped provider DI / pipeline boundary; browser fixtures that write directly into feature repositories are insufficient to prove the production path;
- freshness must be derived dynamically from authoritative timestamps rather than persisted as a once-computed label;
- local smoke boot currently depends on unrelated mail-provider configuration; a future offline/local provider abstraction may be useful if repeated acceptance work justifies it, but it is not a Creator Centre Product requirement;
- pre-existing frontend bundle-size advisory is unrelated to Audience V0.
