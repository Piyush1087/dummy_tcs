# Brand Preview Stitch reconciliation ledger

Stitch artifacts are selective visual references, not page replacement source. Existing Creator Shop frontend surfaces must be reconciled selectively under frozen Product contracts, Aurora 5.0, canonical copy, runtime authority and repository architecture.

## D01 — Fast Brand Analysis desktop

### GO

- One dominant Understanding Surface.
- Compact recognized-domain cue.
- Active/current idea dominant; resolved phases subordinate; future phase quiet.
- Calm whitespace and no action during active analysis.

### NO-GO

- Incidental header, footer or legal content.
- Exact static glow/pulse behavior or pixel-for-pixel phase positioning.
- Numeric completion interpretation.

### IMPLEMENTATION

- Align phase icons, markers, thread and text to one optical grid.
- Drive completed/current/future state from runtime activity, without fake scripted progression.
- Do not show determinate progress without defensible runtime authority.
- Keep slow-analysis reassurance in the same shell without warning/error treatment.

## Cross-cutting runtime authority

### Fast Brand Analysis

- Runtime—not timers—determines the current phase.
- Do not implement percentages, fake timers, fabricated completion or technical provider/process messaging.
- Generic fallback: `Building your Brand Preview…`
- Slow-analysis reassurance uses the same visual family and frozen copy without warning/error styling.

### Brand Preview variable density

- Audience, Opportunity and Archetype collections are runtime-variable; do not hardcode the normal-density fixture count.

### Recovery

- Recovery actions come from canonical frontend/runtime authority. Do not infer actions from Stitch shell elements or visual affordances.
