# Gatekeeper Stitch reconciliation ledger

Stitch artifacts are selective visual references, not page replacement source. The existing Creator Shop frontend must be reconciled selectively under product contracts, Aurora and repository architecture.

## Family A — URL entry

### GO

- Compact hero-embedded scanner.
- URL/CTA hierarchy.
- Centered, subordinate consent treatment.
- Lightweight centered activity.
- Compact validation treatment.

### NO-GO

- Stitch page chrome, header, footer or navigation.
- Exact hero copy or incidental text.

### IMPLEMENTATION

- Retain the existing homepage and reconcile only the scanner area.
- Map normalized real Gatekeeper/runtime activity to concise user-facing messages where available.
- Do not create fictional timer-driven progress.

## Family B — Recovery

### GO

- Recovery directly beneath the scanner.
- Compact warning surface and recovery choice hierarchy.
- Attached inline expansion.
- Compact mobile stacking.

### NO-GO

- Incidental surrounding page content.
- Unsupported hardcoded recovery eligibility.
- Literal generated CSS tokens.

### IMPLEMENTATION

- Render recovery actions only from canonical authority.
- Preserve `Request Review / Try Again → expansion → Submit Request / Cancel`.
- Use Aurora semantic warning roles.
- Do not infer manual-review eligibility.

## Family C — Pre-scan confirmation

### GO

- Compact desktop modal and mobile bottom sheet.
- Brand/domain context, Industry and subtle `Change`.
- Scan explanation and approximate-time treatment.
- Optional-later work email/Meta note.
- Dominant `Start Brand Intelligence Scan` action.

### NO-GO

- Exact surrounding page or incidental explanatory wording.

### IMPLEMENTATION

- Work email and Meta are optional at this boundary.
- Do not claim verification.
- Do not add Surface progress UI here.
- Give M03 `Change` an accessible hit target.

## Family D — Industry exception

### GO

- Same confirmation lineage.
- Detected-versus-selected Industry comparison.
- Restrained warning state and explicit keep/continue hierarchy.
- Compact mobile bottom sheet.

### NO-GO

- Exact warning copy.
- Literal direct CSS colors.
- Incidental page chrome.

### IMPLEMENTATION

- Require explicit authoritative Industry confirmation.
- Preserve assessed Industry provenance.
- A supported override does not create manual-review actions.
- Use Aurora semantic warning tokens.

## Cross-cutting dynamic activity requirement

Retain the existing homepage's lightweight changing activity character after URL submission, but make it truthful and dynamic:

- Use approximately three or four concise user-facing messages when normalized real Gatekeeper/runtime/admission activity is available.
- Map runtime activity to user-facing language in the frontend.
- Do not expose Gemini, Zyte, crawler, DNS, API or provider internals.
- If granular activity is unavailable, show one truthful generic processing message.
- Do not create fictional timer-driven progress.

This requirement overrides any single static activity sentence in Stitch.
